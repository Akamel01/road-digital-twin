## Required changes

R1. **The stage refines per frame, not per channel — the plan's core design is not wired.** The M3 report claims "Refinement runs per channel inside `views()` generator"; the code refines each camera frame independently (`refine_one(base_c2w, K, img, ...)` at `twin/stages/colour.py:363`), producing a separate 6-DOF correction per frame. The M2 spec is explicit: per-channel extrinsic, 6 DOF × up to 6 channels = 36 shared params, "not per-image"; `refine_channel_extrinsics` exists for exactly this and is never called. Per-frame deltas mean (a) frames of the same channel get different corrections, so `by_channel` in `pose_corrections` aggregates incoherent deltas, and (b) the QA row claim "one row per camera frame carrying channel delta" is false — each row carries its own frame delta. Fix: group views by channel, solve per channel via `refine_channel_extrinsics` (or an equivalent shared-parameter solve inside `views()`), and apply the channel delta to every frame of that channel. This also makes the report's claim true.

R2. **`pose_corrections` in qa.json is fabricated on the common path.** `refine_one` returns a per-attempt `_info` dict with the real outcome (`applied`, `reason`, `hit_bound`, `nfev`, `n_inliers`); the stage discards it (`_res, _info` — unused, colour.py:363) and re-derives the summary from deltas via `pose_report`, which hardcodes `applied: true, reason: "converged"` for any non-empty deltas (`twin/pose.py`, unchanged from the M1 review). Net effect: whenever refinement rejects its own corrections (no_improvement / insufficient_inliers — the outcome the M2 review round 3 shows on realistic scenes), qa.json still reports `applied: true, reason: "converged"` with all-zero deltas. That is exactly the zero-filled/fabricated QA M1's N2 and the plan's "no zero-filled QA" forbid. Fix: thread the real per-run outcome into `pose_corrections` — either extend `pose_report` to accept an explicit `applied`/`reason`/`hit_bound` (and per-frame revert count) from the caller, or post-process `pose_report`'s output before writing qa.json, per M1 N2's instruction. `hit_bound` must not be able to contradict `reason`.

R3. **`n_reverted` is hardcoded `0` and `n_skipped` is a mislabelled duplicate.** (a) `n_reverted: 0` (colour.py:424) is a fabricated constant; the info dict that would source it is discarded (see R2). Compute it (count of channels/frames whose refinement was requested but reverted to base) or drop the key — do not ship a hardcoded zero as a measured QA value. (b) `n_skipped: len(cams) - len(usable)` (colour.py:423) is byte-identical to the pre-existing `n_cameras_skipped_outside_sweeps` key and has nothing to do with the M2/M6 semantics of `n_skipped` (channels with no usable frames/anchors kept at calibrated extrinsics). Count channel skips (it falls out of the R1 fix naturally) or rename; do not alias an unrelated existing count onto the new key.

R4. **The required wiring test does not exist.** M3 acceptance names "new wiring test for `zbuffer-pose-refine`"; there is none — no test registers/runs the method, and `tests/test_colour.py`'s existing height test runs only `zbuffer-topk` via the alias. Add a wiring test (CPU, synthetic/fake fixtures) that runs `run_zbuffer_pose_refine` end-to-end and asserts: method string is `zbuffer-pose-refine` in qa.json, `pose_corrections` present (not null) with the frozen key set, `edge_offset_p50_m` present, and topk path emits `pose_corrections: None`. It must fail on the current code (e.g. R1/R2 semantics) until fixed.

R5. **Hold-out circular metric not implemented.** M3 details require the refinement to use the complementary subset (every 4th observed marking held out, `HOLDOUT_EVERY=4`, seed 0) and the acceptance metric (`edge_offset_*`) to be computed on the held-out subset only. Nothing in the stage or in `colour_pose` references the constants; refinement and P50/P95 both consume all markings. Implement the split in the colour path (or reject it explicitly in an ADR) — silent omission leaves the reported edge offsets optimistic by construction.
